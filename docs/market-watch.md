# 竞品监控与短剧参考

2026-11-17，单团队、按产品授权。两个专项共用现有登录、产品上下文、情报与任务，不建立第二套成员或执行状态。

## 六维 AI 竞品监控

入口 `/competitors` 默认进入竞品研究。每个竞品归属于一个产品，配置名称、官网、市场、关注重点和补充来源，并可开启每 6–168 小时自动研究（默认 24 小时）。管理员或有产品权限的运营可创建、修改、暂停和立即研究；只读成员仅可查看。自动研究会调用现有模型与搜索服务并产生相应费用。

每批固定覆盖产品、定价、落地页、内容、广告创意、用户评价。AI SDK Agent 实际使用 Web Search，并可读取公开页面核查；公开广告库、社媒和独立评价可作为发现入口，不能用官网作品冒充广告、用品牌宣传冒充独立评价。无法获取的维度明确为未知，不补造价格、广告量、评价分数或发布日期。搜索来源事件是检索过程记录，不代表每个结果都相关；卡片仅列报告使用的依据，仍需人工核实。

Worker 分为研究与结构化分析两个持久化阶段。保存流式报告、来源事件、模型、配置快照、尝试次数和错误；研究完成后保存检查点，分析失败可从检查点重试。数据库 outbox 和 BullMQ 执行，不依赖浏览器在线。失败最多自动尝试两次，之后可手动重试；同一竞品存在活动批次时返回已有批次，避免重复排队。

六张卡片分别展示当前结论、内容性质、证据链接、采集时间、上次结论与比较说明。首次建立基线；缺少前后依据、官网或市场变更、估算/分析混入时不能确认事实变化。模型给出的变化比较是待人工核实的分析判断，不等于已核实事实。来源依据为报告摘要，不伪装为逐字引文。

管理员或运营逐维“核实并确认入库”，进入现有情报和转任务流程；未知维度不可确认。并发确认只产生一条情报，保留原来的事实/估算/分析性质、来源和缺失时间，不自动变更为事实。结果历史独立保存；配置编辑有版本冲突保护，执行使用创建批次时的配置。

`packages/contracts/src/competitor-research.ts` 定义六维契约，`packages/database/src/competitor-workflow.ts` 管理调度与防重，`packages/agent/src/competitor-research.ts` 定义研究目标、结构化输出与来源范围校验，Worker `workflows/competitor-research.ts` 负责执行和阶段恢复，API `modules/competitors/competitor-profiles.*` 负责授权、配置和确认事务。迁移 0010 新增竞品、批次、事件和入库映射四张表。来源范围校验只能防止模型引用本轮发现之外的 URL，不能证明网页内容真实性或来源相关性。

尚未接入需要授权的广告库/评价平台专用 API，不支持登录态、素材下载/视觉比较、完整评论分页、自动结构化价格字段差异。网页搜索覆盖受来源开放程度影响，不能保证六个维度每次都有数据。

## 页面快照

入口 `/competitors`。选择产品、市场、页面与类型（产品、定价、落地页、内容、广告、评价），设置 1–168 小时的采集间隔。支持修改配置、暂停、恢复、立即采集与人工补录。首次建立基线，后续比较同 URL、同采集方式、同内容性质的最近成功快照。网页事实、人工事实、估算、分析判断分别比较，避免把不同口径误判为页面变化。

快照展示请求/完成时间、尝试次数、错误、来源、前后全文与新增/移除的行。文本变化需要运营核实；广告投放量、收入、转化率等无法取得的数据没有默认值。页面正文最多 30,000 字符，页面下载最多 1.5 MB，单次请求 20 秒，至多 3 次重定向。登录页、反爬挑战、动态渲染和非 HTML 内容可能失败，允许手工补录并标注性质。

“核实并确认入库”由管理员或运营显式触发，产生一条带快照证据的竞品情报，再在情报详情创建选题/建联任务。相同快照并发确认只生成一条情报；各次快照独立保留。入库记录的 `sourceUrl` 仍为真实来源，去重标识附快照 ID。人工确认不将估算或分析改写为事实。

目前采集器比较公开 HTML 的可读文本。广告类型可以监控可访问的公开创意页面，但尚不支持广告账户、Meta/TikTok 素材库 API、登录态抓取、评论分页、截图或图片视觉差异。页面局部文本变化也不自动意味着产品或价格发生有效变化。

## 短剧参考

入口 `/dramas`。按产品记录剧名、平台、市场、题材、开场钩子、冲突结构、反转、节奏、叙事结构参考、来源、内容性质与备注。支持修改、搜索、只看观测上升。同产品、同剧名、同来源去重；同一个榜单页面可以记录多部剧。

“研究短剧趋势”打开 Agent 研究并带入专项目标。研究仍由现有持久化 Worker 执行，可关闭网页。在完成的短剧研究里点击“整理为短剧参考”，可以阅读报告，选择来源并带入录入表单。运营核实剧名和结构后保存。日常重复研究可把目标复制到定时研究。**当前没有自动榜单连接器，也不会自动把研究建议当作已验证剧目或榜单数据入库。**

每条参考可追加带原链接、观测时间、单位和统计口径的排名、播放量、平台热度观测。禁止未来观测时间；相同剧目、来源、指标、单位、口径和时刻不能重复添加。时间不等于页面发布时间，录入者应使用原始观测时间。

趋势只比较最新事实观测与同来源、同指标、同单位、同口径的更早事实观测：排名下降代表上升，播放量/热度增加代表上升，相等代表持平。估算不参与趋势；缺少可比数据展示“趋势未知”。“观测上升”只代表该来源、该口径，不自动称为热门或飙升；当前未定义通用跨平台“热门/飙升”阈值。

补充钩子、冲突和叙事参考后，可以指定原创方向、负责人、渠道、优先级与截止时间，创建原创脚本选题任务。任务自动附参考来源、结构和原创要求，进入现有任务中心。每条参考关联一个原创选题任务，重复创建返回已有任务。只参考叙事结构，禁止直接复制原剧具体表达、台词、角色或整段素材；交付前审核原创性。任务创建后保留当时参考和要求，修改参考不会悄悄改写已分配任务。

## 持久化与扩展

- `packages/contracts/src/market-watch.ts`：浏览器安全契约与趋势/文本对比纯函数。
- `packages/database/src/schema/market-watch.ts`：监控、快照、短剧、观测；迁移 0007–0009，加任务 `brief`。
- `packages/database/src/watch-workflow.ts`：行锁防止同一监控重复待执行，人工快照在事务中保存，对比同口径基线。
- `packages/agent/src/watch-page.ts`：公开网页正文采集，复用来源采集的 DNS/IP 检查、地址固定与逐跳校验，拒绝内网、云元数据及非标准端口。
- API `modules/competitors` / `modules/dramas`：验证、产品授权、事务与审计。
- Worker `workflows/competitors.ts`：执行与失败记录；主循环约每 15 秒从 DB 补入队，BullMQ 两次尝试、5 秒指数退避，不依赖浏览器或内存定时器。
- Web `features/competitors` / `features/dramas`：懒加载页面，产品切换清理详情选择、重置独立缓存。

`nextRunAt` 在创建请求时推进，暂停不再新建定时请求，已排队的请求继续完成；恢复立即到期。停机后仅补一次到期采集，不回补每个历史周期。采集创建人与 Worker 执行/保存前均检查角色和产品权限；创建人失权或产品归档时定时监控自动暂停，需管理员或有权限运营恢复。任务负责人必须有对应产品权限且可写。

后续连接器应输出可比正文或明确观测口径，复用快照/观测实体、产品权限、Worker 与人工确认边界。不要在 Controller 直接长时间抓取或把生成文本伪装为平台原始数据。

当前列表各返回最近 100 个监控/参考，监控详情最近 30 次快照；历史仍保存在数据库。服务端分页、快照保留策略、截图、结构化价格与评价提取、平台榜单连接器、自动短剧结构提取、一次参考多个原创版本任务、成本和队列隔离仍待扩展。
