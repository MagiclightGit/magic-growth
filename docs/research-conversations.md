# 报告追问与个人会话

2026-11-17。竞品研究和普通 Agent 研究的成功报告均支持「我的追问」，报告、竞品配置与周期监控继续按产品权限共享。

## 使用方式

在成功报告下选择「我的追问」。默认恢复最近会话，也可新建或切换会话。「解读报告」只使用绑定的报告和本人该会话的成功问答，不使用搜索工具；「继续研究」实际调用 Web Search，并可读取公开网页。两种模式均调用已配置模型，后者还会使用搜索服务。

每条问题排入独立后台作业，页面约每 2.5 秒读取本人会话的进度与部分回答。关闭网页不会终止作业，重新打开报告可恢复。执行失败保留部分回答和事件，自动尝试两次，随后可重试该轮或新建会话。一个会话一次只允许一轮未完成回答，防止同一会话的多个窗口产生分叉；不同会话互不混合上下文，共享 Worker 的并发容量。

## 可见性

- 团队原报告：按现有产品权限查看。
- 我的会话、问题、回答、工具事件：仅会话所属用户可读，管理员没有会话读取特权。
- 团队补充：仅本人明确预览并确认分享的一轮问题和完整回答，复制为独立快照，对有该产品权限的成员可见；它仍是待核实 AI 回答。

分享不开放整个会话，不暴露会话/消息 ID，也不自动创建已核实情报、候选、评分、任务或团队记忆。回答可能引用此前个人问题，分享预览明确提示用户检查完整内容；分享是一项明确的公开操作，不能假设模型自动删去了私人信息。多人团队会话、分享撤回及补充研究直接转情报仍待开发。

成员失去产品权限后，私有会话和团队补充均不可访问。停用、角色降为只读、产品归档或产品权限撤销时，Worker 在执行前和保存完成结果前重新检查执行权限。归档后有权限成员仍可查看历史，但不能发送、重试或分享。

## 上下文和恢复

创建会话时保存报告正文、标题、来源批次 ID 和报告完成时间。后续周期报告更新或配置变化不会替换这份快照。每轮读取本会话尚未摘要的成功问答。累计到 8 轮，或超过 4 轮且达到 24,000 字符时，Worker 使用已配置的 AI SDK 模型更新摘要，保留最近 4 轮的原文，并把此前的摘要和新覆盖的问答合并。失败的部分回答不进入摘要或后续上下文。

摘要及其覆盖轮次与成功回答在同一事务保存。摘要失败时按现有队列规则重试，原有摘要和原始消息保留。模型每轮读取绑定报告、当前摘要和未覆盖的近期问答。用户仍可在原会话查看全部原文。摘要只在后台使用，遵循原会话的所有者和产品权限。

每个会话最多 100 轮。原报告与当前问题合计最多 100,000 字符。试点覆盖个人报告会话，模型按需回查旧轮次原文、跨会话检索和研发任务上下文后续评估。

会话创建和消息提交使用客户端请求 UUID 防重；会话行锁保证消息顺序和活动轮次唯一。重试递增 generation，队列 ID 含消息 ID 与 generation，旧作业不能覆盖新一代回答。失败事件与来源保存在本轮事件表中。

## 代码与数据库

- `packages/contracts/src/research-conversations.ts`：浏览器安全契约、模式和上下文限制。
- `packages/database/src/schema/research-conversations.ts`：私有会话、消息轮次、事件和团队补充四张表；初始迁移为 `0011_stormy_inhumans.sql`。滚动摘要使用 `0017_mute_aaron_stack.sql` 增加可空的摘要字段，已有会话从下一轮开始按阈值压缩。
- API `modules/research-conversations`：源报告产品授权、本人归属校验、消息事务、重试及分享快照。列表和详情统一按真实登录用户授权，忽略客户端声明的 owner。
- Worker `workflows/conversations.ts`：DB 待入队补偿、AI SDK 执行、权限复查和失败记录；不进入共享研究/提取工作流。
- Agent `follow-up.ts`：固定报告快照、滚动摘要和有序问答；沿用已有模型中转站。
- Web `features/research-conversations/report-follow-ups.tsx`：个人会话、AI Elements 执行过程、Streamdown 回答与分享预览。

## 验证

`pnpm test:conversations` 仅用于本机数据库、Redis、API 与 Worker。合成数据测试不调用付费模型：临时暂停本地队列，验证提交事务后立即将合成回答标为测试结果；最终恢复队列，并让真实 Worker 验证失权成员的作业在调用模型之前失败。临时账号、产品、会话、分享和队列作业会清理。不要同时在该本地队列上进行其他手动测试；队列原本暂停时不恢复它，也不宣称执行了 Worker 检查。

覆盖不同用户与管理员隔离、原报告快照固定、竞品/普通报告两类来源、消息并发防重和顺序、私有事件/历史、逐轮分享和会话访问边界、重试 generation、只读角色、归档及撤销产品权限。

滚动摘要试点使用合成会话，通过本地 Worker 调用已配置模型。第九轮生成覆盖第 1 至 4 轮的摘要，并从中准确复述第一轮的项目代号。数据库保留全部九轮原文，测试数据已清理。
