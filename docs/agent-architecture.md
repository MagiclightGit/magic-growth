# 情报 Agent：首期架构决策

决策日期：2026-11-17。状态：AI SDK 已确认；BullMQ + Redis 作为配套实施方案。本文描述完整设计目标，不代表全部能力已上线。当前已实现独立 Worker、基础队列/每日调度、运行记录与报告、AI SDK Web Search 适配；结构化入库、业务记忆、阶段恢复与每日摘要待实现。实际交付见 [开发说明](./development.md) 和 [TODO](../TODO.md)。

## 1. 技术分工

| 层次     | 方案                            | 职责                                                     |
| -------- | ------------------------------- | -------------------------------------------------------- |
| 网页     | React + shadcn/ui + AI Elements | 研究目标、对话、运行过程、工具结果、证据与日报           |
| 业务 API | NestJS + Better Auth            | 成员准入、权限、研究配置、手动运行、取消、查询与进度订阅 |
| Agent    | AI SDK 的 ToolLoopAgent         | 模型调用、受限工具循环、结构化分析与输出                 |
| 后台执行 | 独立 Worker + BullMQ + Redis    | 定时调度、持久队列、并发限制、退避重试与运行恢复         |
| 业务存储 | PostgreSQL + Drizzle            | 会话、配置、运行阶段、来源、证据、情报、摘要与审计       |

首期采用单个研究 Agent。不同时引入 LangGraph、Mastra 或 Codex 运行时。实现前按安装版本核对 AI SDK 的 API；初始适配器使用 OpenAI 模型与 Web Search；本机已通过兼容 Responses 的 packycode 中转站配置 gpt-6.1-sol 并验证原生 Web Search 与后台研究链路，保留替换 provider 的边界。

## 2. 运行入口与生命周期

网页发起和每日定时使用同一执行路径：创建运行记录 → 入队 → Worker 执行 → 持久化结果 → 网页读取和订阅进度。创建记录与入队之间需要可恢复的投递机制，例如事务 outbox 与幂等 job ID，避免数据库有记录但未入队。

HTTP 请求仅负责提交任务，不承载长时间研究。网页关闭或网络断开不取消任务；重新打开后先读持久化状态，再订阅新事件。停止任务需显式提交取消请求，Worker 在可取消边界处理。所有查询、订阅、工具读写均按工作区和角色校验权限。

后台 Worker 在服务端持续运行，前端是否在线不影响定时任务。持久化 Redis、PostgreSQL 和定时配置；明确时区、重叠运行规则、漏跑补偿、部署重启后的恢复，不能仅使用进程内计时器。

## 3. 研究流程

1. 读取研究目标、产品、市场、排除条件、预算、上次成功时间及近期相关情报。
2. 通过搜索发现候选来源；对已确认来源优先使用 API、RSS 或网页读取。
3. 保存来源、获取时间和允许保留的原始证据。
4. 对内容做摘要、分类、匹配解释与候选去重；后端执行确定性的唯一约束与精确去重。
5. 经结构化校验后保存候选情报，供人工确认；模型推断与原始事实分开。
6. 基于本次有效新增情报生成站内每日摘要；没有新增时明确记录，不编造发现。部分来源失败时保留数据覆盖不完整的提示。

首期工具边界：搜索、读取外部页面、查询授权范围内的历史情报、提交候选来源/情报、生成摘要。不默认提供任意 Shell、数据库 SQL 或外部发布权限。网页内容视为资料，不能据其指令扩大工具权限。

## 4. 上下文与记忆

- 当前运行：由 AI SDK 管理消息与工具循环，设置步骤、耗时、token 与成本上限。
- 会话历史：保存到 PostgreSQL，继续对话时按需加载；聊天记录不自动成为所有成员共享的记忆。
- 长期业务记忆：目标、来源、排除条件、已确认结论和运营反馈优先保存为结构化数据，保留来源和更新时间；按工作区检索，必要时再增加向量检索。
- 上下文预算：网页全文保存于证据存储，模型优先读取摘要与引用；通过每步上下文准备、裁剪或摘要控制长度，维护工具调用与结果配对，不截断成无效消息。
- 每日运行使用新上下文，通过配置和历史检索延续业务记忆，不无限累积单条聊天。

## 5. 失败恢复与幂等

按来源发现、内容获取、分析入库和摘要生成保存阶段状态与结果。已完成阶段在重试时复用；尚未提交成功的阶段可能重新执行。工具外部动作与数据库写入使用幂等键；队列和阶段状态不构成严格的 exactly-once 保证。

记录运行 ID、配置版本、模型/提示词版本、工具事件、证据引用、尝试次数、错误、耗时与成本。默认保存业务进度与可审阅结果，不要求记录模型私有思维链。

## 6. 首期验收

- 网页能发起一次真实研究，看到阶段和工具状态，查看可追溯证据与结构化结果。
- 发起后关闭所有网页，Worker 继续执行；另一位成员能按权限看到同一运行的进度和结果。
- 定时任务在指定时区每天运行，失败和部分失败可见，暂停与恢复生效。
- Worker 重启可恢复或重试未完成阶段，重放不会重复入库或重复生成同版日报。
- 继续对话可加载相关历史；不同工作区/无权限用户无法检索、订阅或读取他人的上下文。
- 搜索不可用、网页无法读取或模型失败时显示真实状态；人工录入与情报管理仍可使用。
- 没有新发现时日报显示无新增；证据不充分时标为待核实，不能伪造来源。

## 7. 待定配置

第一类研究目标、模型与搜索供应商凭据、每日运行时间与时区、单次预算、保留期限及部署环境待定。候选来源可由 Agent 发现，不要求运营先提交完整网站名单；真实搜索和采集验收仍需要可用工具与访问权限。

## 8. 已确认的视觉与对话方向

整体视觉参考 [shadcn 官方 Dashboard](https://ui.shadcn.com/examples/dashboard)：中性色、清晰边框、适度留白、统一卡片和表格层级；品牌色、中文字体和明暗主题细节待页面设计时落实。Agent 采用 [AI Elements](https://elements.ai-sdk.dev/)，与工作台共享样式变量。

AI Elements 可组合 Conversation、Message、Prompt Input、工具状态和来源引用，后续可提供独立研究对话页或侧栏助手，不需要更换现有 UI 底座。首期网页研究入口保留对话式扩展，但不默认扩展为通用聊天产品。

会话与后台运行分别建模：conversation / message 保存交流历史，research_run / run_event 保存执行过程。手动发起的运行关联会话和触发消息，定时运行可以没有会话。追问时由服务端按权限加载关联情报与证据，需要进一步研究时创建新运行；运行中的补充要求是否立即生效由显式状态与控制协议决定，不能只修改页面消息。网页关闭仅断开订阅，不终止后台运行。
