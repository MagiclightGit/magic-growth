# 情报机会评分口径

版本：`opportunity/v1-draft`。更新：2026-11-17。状态：待业务试用校准的规则草案。已接入后台 AI 建议评估、持久化和页面；人工评分复核与完整业务记忆尚未实现。

适用对象：光魔增长工作台中的欧美热点、竞品监控、短剧参考及相关市场情报。使用者为增长负责人、运营和辅助研究的 Agent。首期评估目标为「这条信息是否值得团队在当前产品和市场投入一次验证」，观察窗口默认未来 30 天。

## 1. 评分对象与边界

评分单位是「情报 × 产品 × 目标市场 × 建议行动」。同一新闻对 MagicTattoo 美国获客、MagicLight 英国内容的价值可能不同，需要分别评估。目标产品、目标客户、市场和当前增长目标不明确时，保持待评分。

每条记录独立保存三类结果：

| 结果     | 作用                   | 示例                 |
| -------- | ---------------------- | -------------------- |
| 机会分   | 比较跟进价值，0–100 分 | 机会 75 · 建议验证   |
| 证据等级 | 表达关键判断的支持程度 | B · 有依据，仍需验证 |
| 时效状态 | 表达现在还能否执行     | 有效至 11 月 25 日   |

机会分不表示成功概率、预期收入、实际热度或审核通过。证据等级不等于现有情报的「已确认」状态。模型建议不自动审核情报、不自动创建或执行任务。任务完成数量和当前负责人不影响机会分。

首期使用一套跨类型维度，各类型采用不同证据要求。排序优先在同产品、同市场、同增长目标内比较；不同平台的播放量、不同市场的搜索量不能直接比较。

## 2. 维度、权重与计算

每个维度取整数 0、1、2、3、4，或 null（未知），必须给出理由和支持材料。分数为规则等级，不能凭模型语气使用 3.7 等小数档。

| 维度       | 权重 | 评估问题                                         |
| ---------- | ---- | ------------------------------------------------ |
| 业务匹配 R | 25   | 与目标客户、产品能力和目标市场有多直接的关系？   |
| 行动可行 A | 25   | 团队能否用现有能力开展一个明确、可测量的验证？   |
| 时间窗口 T | 20   | 在机会失效前是否还有足够的准备和执行时间？       |
| 需求信号 D | 20   | 有什么证据说明目标人群正在关注或需要它？         |
| 增量价值 N | 10   | 相对团队已知信息，这条情报带来了多少新决策价值？ |

所有维度齐全时：

```text
机会分 = round((25R + 25A + 20T + 20D + 10N) / 4)
```

只在最后四舍五入一次。各维度不得互相替代：新闻刚发布不代表需求高；官方活动真实存在不代表产品需求上升；能快速出稿不代表适合目标客户。

### 业务匹配 R · 25%

| 档位 | 判定                                                   |
| ---- | ------------------------------------------------------ |
| 0    | 已有证据说明目标客户、市场或产品用途不匹配。           |
| 1    | 仅属相邻行业或泛文化话题，缺少具体产品使用场景。       |
| 2    | 产品使用场景合理，但目标人群或市场只有间接依据。       |
| 3    | 明确匹配目标客户和市场，能对应一项已有产品能力。       |
| 4    | 满足 3，且直接对应当前已记录的增长目标或核心用户痛点。 |

目标客户画像或增长目标未配置时，不自行假定「纹身相关就对增长有用」；无法判断的部分取 null。4 分必须引用实际业务目标或用户研究记录。

### 行动可行 A · 25%

| 档位 | 判定                                                             |
| ---- | ---------------------------------------------------------------- |
| 0    | 已知当前无法合法或实际执行，或产品能力明确不支持。               |
| 1    | 仅有方向性建议，实施依赖较大且尚未解决。                         |
| 2    | 有具体行动，但渠道、素材、资源、访问条件或衡量方式存在明确缺口。 |
| 3    | 有具体行动、目标渠道和衡量指标，能力可满足，关键资源已核实。     |
| 4    | 满足 3，并有低成本的小规模验证方案、负责人确认和停止条件。       |

3–4 分需要真实资源依据。Agent 不得虚构团队排期、预算、授权或成员承诺；负责人尚未确认时，不能给 4 分。衡量指标可以是拟采用的指标，例如合格线索率；不能填写虚构的预期提升。

### 时间窗口 T · 20%

先记录机会截止时间、最晚启动时间和准备周期。窗口由活动日期、平台规则、报价有效期或观察数据确定；采集时间不作为发布时间。以下天数均按目标市场时区的自然日计算，准备周期由负责人确认。

| 档位 | 判定                                                                        |
| ---- | --------------------------------------------------------------------------- |
| 0    | 该行动窗口已结束，或已知无法在截止前准备完成。                              |
| 1    | 尚可执行，但当前剩余时间仅够必要准备，没有缓冲。                            |
| 2    | 准备后有 1–2 天缓冲；或机会明确在 30 天以后，需要提前观察。                 |
| 3    | 未来 30 天内可执行，准备后至少有 3 天缓冲；或有近期证据支持的持续性需求。   |
| 4    | 满足 3，且来源明确证明未来 7 天内存在值得优先把握的节点，当前准备仍来得及。 |

截止时间或准备周期缺失，且无法判断行动窗口时取 null。持续性需求必须有当前有效性的证据，不能因网页可访问就认定仍有效。4 分不能仅由「发布时间在 7 天内」触发。

活动结束后仍有复盘价值时，为「活动复盘」建立新的建议行动并重新评分，不继续沿用活动前获客行动的分数。

### 需求信号 D · 20%

| 档位 | 判定                                                                                     |
| ---- | ---------------------------------------------------------------------------------------- |
| 0    | 有明确反向证据：目标人群无明显响应，或与建议行动相关的需求在下降。                       |
| 1    | 有事实支持的机会机制或使用场景，但尚无目标人群响应或需求增长证据。                       |
| 2    | 至少一个可追溯的直接响应信号，例如目标用户询问、评论需求或相关搜索数据。                 |
| 3    | 有两个独立直接信号相互支持，或同一可比口径中至少两个时间点显示增长；记录基线和样本限制。 |
| 4    | 满足 3，且至少一项来自已核实的目标客户行为或内部验证，并达到预先记录的业务阈值。         |

未找到信号且无法支持具体机会机制时取 null；有合理且有依据的机制但未证实增长时为 1，两者不能混淆。明确标注「未证实增长」，不写「热门」「飙升」。

所谓增长必须注明指标、平台、市场、统计窗口、采集时间和可比基线；百分比需保留分子分母。没有团队基线或预设阈值，不能给 4 分。多个转载、同一作者的跨平台转发不算独立信号；零数据或来源不可访问不代表需求为零。

### 增量价值 N · 10%

| 档位 | 判定                                                           |
| ---- | -------------------------------------------------------------- |
| 0    | 与已有条目重复，没有新增事实或行动影响。                       |
| 1    | 补充背景或措辞，未改变团队的判断。                             |
| 2    | 新增一项可核实事实或来源，可完善已有方案。                     |
| 3    | 新事实足以改变选题、渠道、受众或验证优先级。                   |
| 4    | 揭示此前未记录的重要机会或风险，并能明确说明需要改变哪项决策。 |

必须与团队已有情报或明确的研究基线比较。未检索历史时取 null；不能把「模型第一次看到」当作新机会。重复内容合并来源，避免通过反复采集占据榜单。

## 3. 证据等级与执行门槛

先列明支撑建议行动的关键断言，再按最薄弱的关键断言确定等级。非关键背景资料的缺失不自动降低全部证据，但要记录限制。来源数量、域名知名度或「官方」标签不能单独决定等级。

| 等级         | 判定                                                                                            | 建议处理                       |
| ------------ | ----------------------------------------------------------------------------------------------- | ------------------------------ |
| A · 依据充分 | 所有关键断言有可追溯、适用且已人工核实的直接证据；增长/效果断言满足相应数据要求，无未解决冲突。 | 可按机会分进入人工排期。       |
| B · 有依据   | 关键事实可追溯，建议行动的逻辑成立，但效果仍待验证或直接证据尚未人工复核。                      | 可安排小规模验证，不承诺效果。 |
| C · 依据偏弱 | 关键断言依赖二手概述、单方说法、片段或无法复核的推断。                                          | 优先补证，暂不列为立即执行。   |
| U · 待补证   | 缺关键来源、无法定位支持内容、来源冲突未解决或缺少必要上下文。                                  | 不进入执行优先级榜单。         |

Agent 最多建议 B/C/U；A 必须由有写权限的人工复核者确认，并保存证据与理由。已审核入库不自动升级为 A。来源失效时保留历史证据和核查时间，重新评估当前等级；曾核实的历史事实不因暂时抓取失败直接判假。

确认不相关、同一机会无增量的重复项、行动窗口已结束或已知不可执行的条目，标记对应原因，从当前可执行机会榜单排除，不以总分掩盖。已证实错误的信息撤回相关判断并保留审计。

## 4. 未知值与分数展示

0 表示有依据的低价值判断，null 表示无法判断；不能用 0、平均值或模型猜测填补未知。

只要有一个维度未知，总分为空，显示「待补评 · 已评估权重 75%」等状态。覆盖率等于已评分维度的权重之和；不把已知部分重新归一到 100 分。

详情可以展示理论范围：下界为已知加权贡献之和，上界为下界加未知维度全部取 4 的贡献；下界向下取整，上界向上取整。该范围仅表达缺项带来的可能区间，不是统计置信区间。列表不把范围下界当作正式机会分。

例如 R=3、A=3、T=3、D=null、N=2：已评估权重 80%，范围 57–78，总分仍为空。优先提示「补充需求信号」，不显示「机会 72」。

具备完整分数但证据为 C/U，仍显示「建议分 75 · 待补证」，不显示立即执行标签。没有审核、没有可执行窗口或没有负责人确认时，分数不能替代这些门槛。

## 5. 分档、排序与页面文案

以下阈值为试用起点，尚未通过业务结果验证：

| 分数   | 标签     | 对应行动                                         |
| ------ | -------- | ------------------------------------------------ |
| 80–100 | 优先评审 | 优先人工核实资源与风险，决定是否启动小规模验证。 |
| 60–79  | 建议验证 | 纳入本周候选，补齐验证计划后排期。               |
| 40–59  | 持续观察 | 关注新增证据，暂不占用主要执行资源。             |
| 0–39   | 暂缓跟进 | 保留资料，目标或证据改变后再评。                 |

先分「待补评/补证」「可评审」「不再适用」队列。可评审需五维完整、证据 A/B、行动可执行、窗口有效且条目未被标记不相关。同一队列内按分数降序，再按最晚启动时间升序、证据 A 优于 B、评估时间降序排列；缺失最晚启动时间排在已有明确时间之后。逾期未复核的分数不进入当前执行榜单。

列表「进展 / 表现」列可显示「机会 75 · 建议验证」和「关联任务 1 · 进行中」两行；审核状态、执行进度和证据等级保持独立语义。详情展示各维度、理由、支持材料、缺口、计算版本和复核记录。暂无评分的历史情报显示「未评分」，不批量生成装饰分数。

## 6. 各情报类型的证据要求

| 类型          | 可接受的事实与数据                                                              | 必须避免的推断                                                  |
| ------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 欧美热点/节日 | 官方活动日期、目标市场文化背景、可追溯的搜索/互动信号、目标客户访谈。           | 节日存在 = 纹身需求增长；全球热度 = 美国纹身师需求。            |
| 竞品监控      | 带时间的前后页面/价格/功能快照、适用地区、实际访问条件和公开评价。              | 页面更新 = 转化提升；广告可见 = 广告高效；估算收入 = 实际收入。 |
| 热门/飙升短剧 | 平台榜单与统计窗口、同口径历史排名/播放数据、市场与题材、可追溯的叙事结构分析。 | 单次高播放 = 飙升；叙事可参考 = 素材可直接商用。                |

竞品 D 评估目标用户响应或需求，不能把「竞品做了」本身算成用户需求。短剧的原作热度与其结构适用于自有产品是不同断言，后者需要单独论证。无法取得数据时保留未知，允许建议「先补采基线」。

## 8. 评估记录与更新

后续实现至少保存以下信息；本节是设计要求，不代表已有字段：

| 信息       | 要求                                                                      |
| ---------- | ------------------------------------------------------------------------- |
| 评估上下文 | 情报、产品、目标市场、目标客户、增长目标、建议行动与评估时点。            |
| 评分快照   | 规则版本、五维档位或 null、逐维理由、支持证据引用、未知原因和待补问题。   |
| 证据记录   | 关键断言、来源 URL、支持内容、发布/发生/采集时间、指标口径及适用范围。    |
| 汇总结果   | 总分或 null、覆盖率、证据等级、时效状态、最晚启动时间、下次复核时间。     |
| 生成与复核 | Agent/模型版本、输入情报 revision、评估者、复核者、人工修改前后值和理由。 |

Agent 提出逐维建议，服务端验证取值、计算总分、应用门槛；不接受模型直接指定最终总分。来源内容仅作为证据，不作为修改评分规则或权限的指令。人工可修改维度和理由，不直接覆盖总分；修改留审计。情报 revision 改变后，旧评分标记待复核，不能悄悄当作当前结果。

默认复核间隔：热点/短剧 72 小时，竞品变化 7 天；这些间隔也是试用参数。活动到达最晚启动时间或截止时间时优先更新时效状态，关键证据/业务目标发生变化时提前复核。刷新采集时间不延长分数有效期；未取得新证据时记录复核未完成。复核任务失败不删除原记录，展示上次结果与过期状态。

规则版本升级后保留历史快照。新规则先用于新评估，旧条目按需重评，不批量覆盖历史排序依据。首期由共享契约定义规则、后端计算、独立 Worker 阶段辅助评估、前端只展示；不在页面硬编码总分，不将评分逻辑塞入来源采集器。

## 9. 试用校准与交付边界

先选取 20–30 条覆盖热点、竞品和短剧的真实条目，由两位运营独立评分后核对分歧；重点检查 0 与未知、需求与热度、事实与判断的区分。记录差异原因并修订档位示例。此样本用于发现歧义，不足以证明评分能预测增长。

后续关联实际验证结果：是否采纳、启动耗时、完成情况、预先选定的业务指标与未采纳原因。每两周回看高分是否值得做、低分是否漏掉机会；样本不足时不随意拟合权重。调整权重/阈值必须发布新版本，保留变更理由。

已交付规则契约、数据库评估快照、Worker 独立阶段、AI 逐维建议、服务端总分计算与缺失背景上限、页面展示和重新评估入口。补充背景支持增长目标、客户、行动、准备周期及资源确认；并非团队全局业务配置。历史比较仅查询最近 50 条同产品同市场情报，缺少历史时增量价值保持未知。

候选内容变化、情报内容或状态变化、规则版本不同、超过默认复核间隔时，读取接口将评分标记为待复核；不自动付费重评。活动结束会按市场默认时区标记窗口结束，US/UK/EU 分别采用纽约/伦敦/巴黎，Global 在日期于所有时区结束后失效；尚不支持每条记录自定义市场时区。相同内容、背景、版本在同一 UTC 日复用已有结果，失败时可重试；不同背景保留独立快照，页面展示最近请求的版本。
