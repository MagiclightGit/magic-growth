# 创作者建联与 Gmail 试接

## 环境

- 本地入口为 `http://localhost:5173/outreach?product=<产品标识>`。管理员访问全部产品。运营与只读成员使用各自获授权的产品。归档产品可回查已有记录。
- 迁移 `0018_dazzling_hobgoblin.sql` 新增建联表。按开发文档启动本地 PostgreSQL 和 Redis，执行 `pnpm build` 与 `pnpm db:migrate`，再启动 API、Worker 和 Web。
- 由团队 Workspace 管理员批准 Gmail OAuth 客户端与专用测试邮箱。为该邮箱获取支持离线访问的 OAuth 刷新令牌，授权 `https://www.googleapis.com/auth/gmail.send` 和 `https://www.googleapis.com/auth/gmail.readonly`。后者用于读取原线程和搜索已发送邮件。
- 将 `GMAIL_PILOT_ADDRESS` 与逗号分隔的 `GMAIL_PILOT_RECIPIENTS` 配置到 API 和 Worker，受控收件地址必须由团队明确批准。将 `GMAIL_PILOT_CLIENT_ID`、`GMAIL_PILOT_CLIENT_SECRET` 和 `GMAIL_PILOT_REFRESH_TOKEN` 配置到 Worker。重启服务后，等待页面显示已连接。同一个试接地址的 Worker 实例应使用一致的配置。
- 授权过期或撤销后，为同一个邮箱重新授权并更新 Worker 配置。暂停和恢复由管理员在页面操作。更换试接地址会切换到该地址的队列和退订记录，旧邮件仍可从原产品的创作者详情查询。

## 创作者和导入验收

启动并迁移本地服务后，运行 `pnpm test:products` 验证 CSV 混合行、并发导入和跨产品访问。

1. 使用获授权的运营账号打开产品，手动录入 URL 和可选邮箱。输入无效链接应就地显示字段错误。保存后刷新详情，确认原始链接、手动录入来源与「未核验」状态。
2. 下载模板，上传 UTF-8 CSV。混入一个全新链接、一个等价链接、一个错误链接。预览应统计可导入、重复和失败。确认后校对结果与行号，并从创作者详情打开原批次。重传同一个文件，再修正错误行重传。
3. 在不同浏览器会话同时导入同一份文件。两次结果相加应只新增一条等价链接记录。用其他产品的运营账号直调列表、详情、批次、邮件及写接口，应返回拒绝；只读账号在授权产品读取成功、写入返回拒绝。
4. 桌面和移动端分别切换浅色和深色，检查产品选择、手动录入、上传、批次、邮件详情和页面宽度。使用 `VERIFY_UI_ROUTES=/outreach?product=<产品标识>` 和本地测试账号环境变量运行 `pnpm verify:ui`。

## Gmail 验收

1. 用获授权的运营账号，从创作者详情向受控地址提交测试邮件。用同一个请求标识重复提交相同请求应返回原邮件记录。关闭页面并等待 Worker，之后在 Gmail 对照实收邮件、站内 Gmail 邮件 ID 和线程 ID。
2. 安排一次未来的跟进。无回复时核对跟进出现在原线程。对另一封邮件在原线程回复，等站内出现回复后核对待发跟进变为「已停发」。重复同步回复及重启 Worker 后，站内同一 Gmail 回复只显示一次。
3. 暂停邮箱后提交待发邮件，确认队列保留且仍同步回复。登记退订或从试接地址对应的外部收件邮箱回复简短的 `unsubscribe`，再恢复邮箱。同一试接邮箱向该受控地址的其他产品邮件也应停止发送。
4. 暂停邮箱并入队，撤回运营的产品授权或归档产品后恢复。Worker 应停止对应任务。模拟 Gmail 授权失效后恢复同一邮箱授权，核对积压回复。
5. 发送结果未知时，Worker 按固定的 RFC Message-ID 搜索 Gmail 已发送邮件。至少等待两分钟后，由管理员在 Gmail 核对，再从邮件记录授权重试。Worker 将在重新发送前再次搜索。关闭页面或重启 Worker 后发送记录和核对状态仍保留。

试接限制为一个配置中的邮箱、受控收件地址和每封原信一次跟进。回复回传展示 Gmail 提供的文本摘要。退订支持人工在记录中登记，以及识别受控收件地址发送的简短退订回复。实际验收记录应保留测试地址、账号角色、Gmail 实收和回传证据。
